    條目¶

    W09-001　讓每個功能頁 extends MenuAbstract 並只重寫 show()¶

    • 關鍵字：MenuAbstract MenuPopular show() setRoot v2.menu TilePane
    • 來源：第十七課 01:30–03:30｜L17_第十七课_教學筆記.md
    • 要點：MenuAbstract 是第十六課抽出的功能頁共用基底，統一管 show() / destroy() 這類頁面生命週期。 新增一個功能頁時，只要 extends MenuAbstract、重寫一個 protected void show()，並在 MenuEnum 中指定 該頁的列舉值即可，樣式與切換邏輯由基底類別統一處理，不必每頁重寫。 MenuPopular 是第一個走完這個流程的頁面。
    • 程式碼：
    package v2.menu;

public class MenuPopular extends MenuAbstract {
    @Override
    protected void show() {
        // 原本寫了 System.out.println("Popular"); 後來又刪除了
    }
}

    // 口述定案的頁面骨架（第十七課 3.2 節骨架）
root.setVgap(10);
root.setHgap(10);

setRoot(root);   // L16 沿用：MenuAbstract 提供的根節點設定
    • 坑：⚠️ MenuAbstract 只在第十七課出現，第十八、十九課筆記完全沒有提到它； 引用本條時請以第十六課筆記為準，不要把後兩課的畫面檔名當成 MenuAbstract 的來源。 ⚠️ MenuPopular 的套件路徑有三種互斥說法：v2/menu（v000，有逐字 package v2.menu;）、 t.t.menu（v002 推測）、ui.menu（v004）；僅 v000 有可逐字引用的 package 敘述。 ⚠️ show() 的存取修飾層級在不同切片被記成 protected 與 public 兩種。
    • 相關：頁級 見 W04（選單系統與視圖切換）；條目 見 W14-012

    W09-002　功能頁用 TilePane 當容器，間距靠 setVgap／setHgap¶

    • 關鍵字：TilePane setVgap setHgap setSpacing FlowPane addAll
    • 來源：第十七課 08:00–10:30、16:00–19:00｜L17_第十七课_教學筆記.md
    • 要點：口述理由是「所有的子組件裡面用 Root，其實都是按照指定的比例去分佈的， 所以我們用 TilePane 其實是比較好的」；FlowPane 是被提到的替代方案但沒採用。 TilePane 沒有 setSpacing，要製造間距只能用 setVgap / setHgap。
    • 程式碼：
    // 口述 a003：兩者皆為 10；畫面 v004 記為 12
root.setVgap(10);
root.setHgap(10);

    // 畫面 v004 記錄的版本
root.setVgap(12);
root.setHgap(12);

    root.getChildren().addAll(reloadEventButton, exitGameButton, searchAccountButton,
        banUnbanButton, modifyNxButton, sendGlobalMailButton, searchPlayerButton);
    • 坑：⚠️ 講者照本能反應寫 root set spacing(...)，實測「它沒有 spacing」—— 照抄 setSpacing 會編譯失敗，必須改用 setVgap / setHgap。 ⚠️ 間距數值口述 10、畫面 12，無法定案。 ⚠️ 第十七課 10:30 的除錯記錄：只 addAll 一顆按鈕會導致「沒有給它加進去」， 其餘按鈕不會出現在頁面上。
    • 相關：條目 見 W09-003、W09-001

    W09-003　「常用功能」的按鈕清單有 5 顆與 7 顆兩套並存說法¶

    • 關鍵字：MenuPopular reloadEventButton sendWorldNXButton searchItemButton ButtonUtils ButtonExt
    • 來源：第十七課 01:30–03:30、08:00–10:30、10:30–13:00｜L17_第十七课_教學筆記.md
    • 要點：口述層與畫面層給出兩份完全不同的按鈕清單，數量與內容都對不上。 口述是「重載事件、發送全服公告、發放全服點券、發送全服經驗、物品查詢」5 顆； 畫面 v002 是「重啟機器、退出游戏、搜索账号、封禁解封、修改点券、发送全体邮件、搜索指定玩家」7 顆。 「修改点券」vs「发放全服点券」、「发送全体邮件」vs「发送全服公告」應是同一功能的兩種說法。

Button reloadEventButton  = ButtonUtils.createPopularButton("重载事件");
Button sendWorldMessageButton = ButtonUtils.createPopularButton("发送全服公告");
Button sendWorldNXButton  = ButtonUtils.createPopularButton("发放全服点券");

    • 相關：條目 見 W09-004、W09-013

    W09-004　用工廠方法 createPopularButton 產出功能頁專用按鈕¶

    • 關鍵字：createPopularButton createAppButton ButtonUtils ButtonExt ButtonBase ButtonView
    • 來源：第十七課 03:30–05:30、05:30–08:00｜L17_第十七课_教學筆記.md
    • 要點：功能頁的按鈕不直接 new Button()，而是交給一個靜態工廠方法統一產出樣式。 入參是一個 String text。同一個職責的按鈕工具類在本課被記成四個名字， 套件路徑也被記成三種，一律並列如下，無法判定最終類別名。
    • 程式碼：
    // ① v001（口述亦稱 button utils / button util / ButtonUtil）
//    推測路徑 view/menu/ButtonUtils.java
public static Button createPopularButton(String text) {
    Button button = new Button(text);
}

// ② v002 / v003：ButtonExt.java，畫面推測套件 ui.util
public static Button createPopularButton(String text) {
    region.setStyle("-fx-border-color: rgb(225, 225, 255); -fx-pref-width: 115; -fx-pref-height: 30;");
    button.setGraphic(region);
    return button;
}

// ③ v004 / v005：ButtonBase.java，畫面記套件 ui.kit、專案路徑 ui/base/
public static Button createPopularButton(String text) { ... }

// ④ v006：src/main/java/tools/ui/ButtonView.java（唯一有完整路徑，但與其他切片衝突）
public static Button createIconButton(String text) { ... }
public static Button createColorButton(String text, String color) { ... }
public static Button createPopularBoardButton(String text) { ... }
    • 坑：⚠️ 方法名 createPopularButton vs createAppButton：口述全程 createPopularButton， v001 畫面記為 createAppButton 且註解自述 text 暂未用到，與口述「把 text 直接傳進去就好了」矛盾。 ⚠️ 四種類名（ButtonUtils / ButtonExt / ButtonBase / ButtonView）與 套件路徑（view/menu、ui.util、ui.kit／ui.menu、ui.base）在本課全部並存，照抄任一組都可能不符。 ⚠️ ButtonView 的三個方法出現在本課最後 2 秒切片（v006）， 且該切片解析極稀薄（20:34 之後約 3 分鐘畫面無法從素材還原），疑為後續版本。 ⚠️ 第十九課筆記又記到 UI.buttonUI.createPopularButton("发送全员信件(弹窗)", 0)， 多了一個 int 參數，是第三種簽名。
    • 相關：條目 見 W09-005、W09-007

    W09-005　SVGPath + Region.setShape() 做向量圖示，實作後退化成純色方塊¶

    • 關鍵字：SVGPath setContent Region setShape setPrefSize setGraphic
    • 來源：第十七課 05:30–08:00、10:30–13:00、16:00–19:00｜L17_第十七课_教學筆記.md
    • 要點：口述唯一一段方法論：「為什麼要用 svg 而不用圖片，是因為我們這裡可能會對它的顏色做一些調整， 用圖片的話就沒辦法隨心所欲地改變我們的圖片的顏色」，並補一句 「比較複雜的情況下的話，我們還是得用圖片」。做法是 SVGPath.setContent() 載入 <path d="..."> 座標， 用透明的 Region 包住並 setShape()，再 button.setGraphic(region)。 實作到後段發現 SVG 太麻煩，實際落地退化成一個純色方塊 Region 當圖示佔位符。
    • 程式碼：
    SVGPath svgPath = new SVGPath();
svgPath.setContent("M25.3 104.2c-1.3-1.6-3.8-3.3-6.5-4.5-3.4-1.6... ");

Region region = new Region();
region.setShape(svgPath);

// 口述 a001：依阿里雲盤實測 155 x 85；不給尺寸就「展示不出來」
region.setPrefSize(155, 85);
region.setStyle("-fx-pref-width: 155; -fx-pref-height: 85; "
              + "-fx-border-color: red;");        // 紅框僅為除錯用

button.setGraphic(region);
return button;

    // 最終定案的純色方塊圖示（第十七課 3.5 節）
region.setStyle("-fx-background-color: #2F64C0; -fx-pref-width: 25; -fx-pref-height: 25;");
