    W11　指令管理¶

    本頁為主題式重組，內容全部來自原始的 42 份逐片教學筆記，未引入外部資訊。 每條可獨立引用；條目 ID 穩定，請勿隨意改號。

    ⚠️ 本頁最重要的一項揭露：reloadGMCommand(List<GmCommand>) 這個方法名在素材中並未逐字出現。 它是筆記依口述「我們的 reload 也不能以常規的方式去 reload」的語意所取的重建名稱， 不是畫面逐字記錄的原始碼（出處標為「口述語意重建」）。 另一半必須同時保留的事實是：畫面層確實記到另一組重載方法 ——reloadCommands(List<GoCommand>) 與 reloadCommands(List<GvCommand>)， 這兩個型別與方法名是素材有的，走的是「全新註冊」路徑，與口述的「刪舊＋插新」正面衝突。 換言之：reloadCommands 這兩個型別是素材有的；reloadGMCommand 這個名字是筆記推補的。

    W11-001　註冊指令管理模組：加一個 MenuCommand 類別¶

    • 關鍵字：MenuCommand MenuAbstract MenuEnum show() COMMAND v2.menu
    • 來源：L23 00:00–04:00｜L23_第二十三课_教學筆記.md
    • 要點：要新增一個選單模組，做法固定兩步：新增 MenuCommand extends MenuAbstract（覆寫 protected void show() 決定右側內容）， 然後在 MenuEnum 枚舉註冊一筆，左側導覽列就會自動長出「指令管理」按鈕。 講者明說「介面相關的東西都是一樣的，直接抄一下就行了」——上一課的玩家管理 MenuPlayer 就是同一副骨架。 註冊前點擊會顯示「功能在开发中，敬请期待！」，註冊後按鈕才真正可切換。
    • 程式碼：

    package v2.menu;

public class MenuCommand extends MenuAbstract {
    @Override
    protected void show() {
        VBox root = new VBox();
        // 後續將貼上佈局代碼
    }
}

    // MenuEnum.java
COMMAND("指令管理", MenuCommand.class),

    • 坑：⚠️ 筆記的畫面理解層對類別名辨識有明顯失真（同一個角色被記成 MenuCommand／StoreCommand／ServerCommand／ServerGUI 等）， 以口述為準；畫面讀到的檔名照錄但不採信。
    • 相關：見 W10（玩家管理）、見 W14-008（menuList 加字串就長出選單按鈕，機制同型）

    W11-002　切換介面時務必把定時任務 cancel 掉¶

    • 關鍵字：Timer destroy() timer.cancel() timer = null 銷毀 背景任務殘留
    • 來源：L23 00:00–04:00｜L23_第二十三课_教學筆記.md
    • 要點：上一課留了一個定時刷新任務，銷毀的時候沒把它銷毀掉、切換介面時也沒銷毀，導致背景任務殘留。 本課第一件事就是重寫 destroy()：timer 不為 null 時先 cancel()，再 timer = null。 口述理由是「切換介面以後不需要刷新了」——資源要跟著介面的生命週期走，不要跨頁殘留。
    • 程式碼：
    @Override
public void destroy() {
    if (timer != null) {
        timer.cancel();
        timer = null;
    }
    super.destroy();
}
    • 坑：⚠️ 漏掉 cancel 的症狀是「表面正常、背景一直在跑」—— 介面切走了但定時任務仍持有資源，久了會以非預期的方式干擾新頁面。本課開頭就在修這個。 ⚠️ 筆記註明這段是上一課的遺留 bug，不是本課新功能。

    W11-003　center 改用 Pagination 並抽出 createTableView()¶

    • 關鍵字：Pagination setPageFactory createTableView setEditable PAGE_SIZE 分頁
    • 來源：L23 04:00–08:00、32:00–36:00、36:00–40:00｜L23_第二十三课_教學筆記.md
    • 要點：指令資料來自資料庫，不能像玩家管理那樣直接把 TableView 放進 center，要改用 Pagination。 講者給的兩個理由是：「不會說我全查，查得慢」＋「既然原來就不在內存裡面去，我們就沒必要把內存弄得很大」， 沿用的是配置管理的分頁查詢模板。setPageFactory 傳進來的 index 就是頁碼，裡面 create TableView 放進 Pagination。 另外必須 setEditable(true)——後續「改／保存」兩步都建立在儲存格可編輯之上。
    • 程式碼：
    Pagination center = new Pagination();
center.setPageFactory(index -> {
    // 先建立「空表格」，資料在背景 Task 完成後回填
    TableView<GmCommand> tableView = createTableView();
    // ... searchLoading.execute() ...
    return tableView;
});

private TableView<GmCommand> createTableView() {
    TableView<GmCommand> tableView = new TableView<>();
    tableView.setEditable(true);   // 口述：後續「改／保存」需要
    // ...
    return tableView;
}
    • 坑：⚠️ 忘記 setEditable(true)，後續「改／保存」功能會直接不能用（setOnEditCommit 不會觸發）。 ⚠️ setPageFactory 的 index 基準在筆記裡畫面與口述直接矛盾（見 W11-009 的 offset 坑），實作前必須自行驗證。

    W11-004　把查詢抽成可複用的 onSearch¶

    • 關鍵字：onSearch setOnAction searchInput searchButton levelComboBox 回車查詢 Platform.runLater
    • 來源：L23 20:00–24:00｜L23_第二十三课_教學筆記.md

searchButton.setOnAction(event -> onSearch(center, searchInput, levelComboBox));

    String searchText = searchInput.getText();
    int selectedIndex = levelComboBox.getSelectionModel().getSelectedIndex();
    // ... 非同步 Task ...
}

    W11-005　等級下拉的位偏移：要 > 0 且減 1¶

    • 關鍵字：selectedIndex gm_level 位偏移 indexOf gmLevel 0 開始
    • 來源：L23 44:00–47:00｜L23_第二十三课_教學筆記.md
    • 要點：UI 下拉選單的第 0 項是「所有」，第 1 項才對應資料庫的 gm_level = 0； 但 getSelectedIndex() 本身是 0 開始，ComboBox 一開始沒選時回 -1。 因此條件必須寫成 if (selectedIndex > 0) 並用 selectedIndex - 1， 否則會出現「想查等級 1，卻把等級 3 也查出來」的現象。
    • 程式碼：

    // 修改前
if (selectedIndex != -1) {
    conditions.add("gm_level = " + selectedIndex);
}

    // 修改後（下拉選單第一項 Index 0 是「所有」，第二項 Index 1 才是對應 gm_level = 0 的玩家指令）
if (selectedIndex > 0) {
    conditions.add("gm_level = " + (selectedIndex - 1));
}

    • 坑：⚠️ 用 != -1 判斷會把「所有」誤當成 gm_level = 0，這是本課實測才抓到的偏移。 ⚠️ 筆記記錄這是逐步修正的過程（!= -1 → > 0 → > 0 ＋ selectedIndex - 1），不是三個並存版本。 ⚠️ 下拉選單的畫面讀值（1000, 1, 2, 3, 4, 5, 12）與口述（GM 0～6 級，最高 6 級）不符，以口述為準。

    W11-006　用 conditions 動態組 WHERE，or 片段必須加括號¶

    • 關鍵字：List<String> conditions String.join like CollUtil.isNotEmpty or and 括號
    • 來源：L23 24:00–32:00、47:00–50:00｜L23_第二十三课_教學筆記.md
    • 要點：查詢條件用 List<String> conditions 逐條收集，最後以 String.join(" and ", conditions) 一次組裝。 講者選這個寫法是因為「我們的 String 它有一個 join 方法……所以我就懶得自己手動拼了」。 關鍵字條件是 command like '%…%' or description like '%…%'。 ⚠️ 這裡的 or 片段一定要用括號包起來：or 的查詢優先級比 and 低， 不括起來會變成 command like … OR (description like … AND gm_level = x)，混查時結果全錯。 講者自評之前沒踩到是因為「之前所有的界面都是只有一個查詢條件」，條件從一個變成兩個就會出問題。
    • 程式碼：
    List<String> conditions = new ArrayList<>();
if (StrUtil.isNotEmpty(searchText)) {
    // ⚠️ 括號不可省：or 的優先級比 and 低，否則混查會出錯（本課 47:00 段的關鍵修正）
    conditions.add(" (command like '%" + searchText + "%' or description like '%" + searchText + "%') ");
}
if (CollUtil.isNotEmpty(conditions)) {
    sql += " where " + String.join(" and ", conditions);
}
    • 坑：⚠️ SQL 注入風險：conditions.add(" (command like '%" + searchText + "%' …)") 是字串直接拼接， 使用者輸入的單引號會破壞 SQL 語法（筆記標明本片未提及，但程式碼本身是示範）。 ⚠️ SQL 欄位名以資料庫語法為準：口述明講「一定要看我們表裡面是怎麼寫的……千萬不要按照我們 Java 的語法來查」， 欄位是 gm_level 而非 level。 ⚠️ 括號修正的實際發生時點存疑：口述 47:00 才當新發現講解，但 36:00–40:00 的畫面截錄已帶括號。

    W11-017　重載第一步：先刪舊（registeredCommands ＋ nameDescribe）¶

    • 關鍵字：先刪舊 registeredCommands nameDescribe getRank indexOf remove ORIIndex toLowerCase
    • 來源：L24 28:00–32:00｜L24_第二十四课_教學筆記.md
    • 要點：改等級不能只改值，必須先刪掉它原來那一條再插新的—— 口述：「如果等級被我們改了的話，它在這裡和在這裡的位置都會發生改變……如果它只是改了 isWork 的話，我們同樣的還是把原來的刪了。 也就是不管怎麼樣，我們要把這條指令對應的原來的位置給刪掉。」 刪舊四步：①registeredCommands 依小寫 commandName get 出 originalCommand，用 getRank 拿到舊等級； ②依舊等級從 nameDescribe 取出該桶；③用 getLeft().indexOf(...) 拿到 ORIIndex， remove(ORIIndex) 刪掉描述（getRight）與名稱（getLeft）；④registeredCommands.remove(commandName)。 刪完之後新值無效就直接 continue；類都載不出來也 continue（「如果這個類都加載不出來，那你也不用重載了」）。

    W11-020　恢復默認：全表 update ＋ 記憶體重置，先刷 UI 再判斷在線¶

    • 關鍵字：resetCommandButton resetAll config_gmcommand gm_level_primitive is_warn ConfirmBox isOnline onSearch
    • 來源：L25 03:39–07:18、07:18–10:57｜L25_第二十五课_教學筆記.md
    • 要點：「恢復默認」是四個按鈕裡最重的：DAO 層一次全表 update 把全部指令還原， CommandExecutor 層再把記憶體清掉重新初始化與註冊，兩者必須成對呼叫。 為什麼是全表 update：「重置默認以後，肯定所有的指令都能變成啟用了，然後我們的 gmlevel 啊，就設置成我們默認的…… 我們之前是不是把默認的給存下來了？我們把默認的給存到這個字段了，那我們就把它設成我們默認的 gmlevel 就好了。」 順序是講者自己修正出來的：「不管服務啟沒啟動，我們應該都把介面給刷新一下」—— 先 onSearch 重畫 UI，再判斷服務是否在線，最後才 resetAll。
