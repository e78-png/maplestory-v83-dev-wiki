    W07　自訂元件庫¶

    本頁為主題式重組，內容全部來自原始的 42 份逐片教學筆記，未引入外部資訊。 每條可獨立引用；條目 ID 穩定，請勿隨意改號。 本頁涵蓋：ToggleSwitch 開關元件（SwitchButton / TextSwitch）、 提示／警告彈窗（ConfirmBox / MessageBox）、字體與顏色常數、 以及共用元件如何擴充成可重複呼叫的工具類別。

    條目¶

    W07-001　用 Rectangle + Circle 手刻 Win11 風格的 SwitchButton¶

    • 關鍵字：SwitchButton StackPane Rectangle Circle ToggleSwitch 40 20
    • 來源：第十一課 08:00–12:00、20:00–24:00、24:00–28:00、28:00–32:00｜L11_第十一课_教學筆記.md
    • 要點：JavaFX 內建沒有開關元件，老師決定自己刻一個模仿 Windows 11 原生 Toggle Switch 外觀的自訂元件。做法是 class SwitchButton extends StackPane（明講「它又不是繼承我們的 button」，是繼承 stack pane），底板用 Rectangle、撥桿用 Circle。 建構子一定要傳 double width 與 double height，理由是「它不會像我們其他的組件一樣會有 一個自適應，它就會縮成一團」。尺寸由 50 25 收到定案 40 × 20；因寬高由呼叫端傳入， 可拉長成 160 與上方輸入框對齊。 講者明講不引第三方 ToggleSwitch 依賴：「那個開關按鈕也不是特別好看」且 「為了（一個開關按鈕）去引一個依賴包進來……成本還是有點大」，加上網路上查不到教學。
    • 程式碼：
    public class SwitchButton extends StackPane {

    private final AtomicBoolean on = new AtomicBoolean(true);
    private final Rectangle rectangle;
    private final HBox rectangleBox;
    private final Circle circle;
    private final HBox circleBox;

    public SwitchButton(double width, double height) {
        // ── 底板：膠囊形 Rectangle ──
        rectangle = new Rectangle(width, height);
        rectangle.setStrokeWidth(1);          // 口述：外邊框寬度設為 1
        rectangle.setArcWidth(height);        // 口述推導後的結論：弧度直接用 height
        rectangle.setArcHeight(height);

        // 長方形不動 → 直接置中
        rectangleBox = new HBox(rectangle);
        rectangleBox.setAlignment(Pos.CENTER);

        // ── 撥桿：Circle ──
        circle = new Circle();
        circle.setRadius(height * 0.75 / 2);  // 直徑 = height * 0.75，半徑再除以 2

        circleBox = new HBox(circle);
        // 上 0、右 6、下 0、左 6（口述）
        circleBox.setPadding(new Insets(0, 6, 0, 6));
        circleBox.setAlignment(Pos.CENTER_LEFT);   // 預設關閉＝居左

        getChildren().addAll(rectangleBox, circleBox);

        initStyle();

        // ── 點擊事件：綁在父容器上，內部任何位置都收得到 ──
        setOnMouseClicked(event -> on.set(!on.get()));
    }

    public boolean isOn() {
        return on.get();
    }

    public void setOnOff(boolean onOff) {
        on.set(onOff);
        initStyle();   // 手動設定狀態後必須重繪
    }
}
    • 測試用主程式（單獨測元件時）：
    // 單獨測 SwitchButton
HBox root = new HBox();
SwitchButton switchButton = new SwitchButton(40, 20);   // 口述最終定案尺寸 40×20
root.getChildren().add(switchButton);

// 拉長成 160 與上方輸入框對齊
TextSwitch wide = new TextSwitch("test", 160, 20);
    • 坑：
    • 沒有動畫是已知缺陷，講者明講「它沒有動畫……動畫確實好像有點難實現，然後所以我就放棄了」。 這是「抄 Windows 11」的複製品，不是原生效果。
    • 同一個類別在四個畫面切片被記成四個名字：口述與 v005 / v007 為 SwitchButton， 但 v002 記成 IntroButton、v003 記成 ItemPane、v006 記成 SelectButton。 套件名同樣分歧（ms.component / mi.component / server.ui.component / server.console.control）。 筆記疑有誤，待查：以口述與多數切片一致的 SwitchButton 為準，不要照抄異名。
    • 狀態欄位型別與名稱有五種寫法：v002 AtomicBoolean isHover、v003 AtomicBoolean isOn、 v004/v005 AtomicBoolean on、v007 SimpleBooleanProperty state；口述全程只提 boolean on（預設 true）與 isOn() / setOnOff()，未提過 SimpleBooleanProperty。
    • 同一個「設定開關狀態」動作有五種方法名：isOn / setOn / set / setOnOff / setSelected。 筆記判斷口述的 setOnOff 與 isOn 配對最穩定。
    • v006 的 Color.rgb 四參數寫法不合法：Color.rgb(0, 165, 100, 111) 這類寫法不是合法的 Color.rgb 呼叫，筆記判為解析誤讀，不可照抄。
    • 相關：見 W07-002、W07-003、W07-004、W07-005、W07-006

    W07-002　StackPane 不能對齊子圖形，形狀要各包一層 HBox¶

    • 關鍵字：StackPane HBox setAlignment Pos.CENTER_RIGHT Pos.CENTER_LEFT getChildren().get(0) ClassCastException
    • 來源：第十一課 20:00–24:00、24:00–28:00｜L11_第十一课_教學筆記.md
    • 要點：SwitchButton 一開始把 Rectangle 與 Circle 直接 getChildren().addAll() 進 StackPane，結果「它关的时候是不是在最左边？开的时候是不是在最右边？」——圓球永遠卡在正中間， 開關等於壞掉。原因是 StackPane 只管堆疊，不管你要的對齊。 解法是「既然我们的图形，它是没办法设置布局或者对齐方式的，那我们就把它包一层。包成什么？HBox」： 底板與撥桿各包一個 HBox，底板固定 Pos.CENTER（它不動），撥桿依狀態在 Pos.CENTER_LEFT / Pos.CENTER_RIGHT 之間切換。 改完之後還要解決「怎麼把形狀再拿出來」的問題。
    • 程式碼（v006 畫面記到的 HBox 包裝 + Padding 版本）：
    public SelectButton(double width, double height) {
    Rectangle rectangle = new Rectangle(width, height);
    rectangle.setArcWidth(height);
    rectangle.setArcHeight(height);

    HBox circleBox = new HBox();
    circleBox.setPadding(new Insets(0, 5, 0, 5));
    Circle circle = new Circle();
    circle.setRadius(height * 0.75 / 2);

    circleBox.getChildren().add(circle);
    getChildren().addAll(rectangle, circleBox);

    initStyle();
}
    • 形狀取出方式的兩條路（筆記中先後出現過）：
    • 欄位化（v005 重構後）——private final Rectangle background; / private final Circle circle;， 之後 initStyle() 直接用，不再傳參。口述：「它已经是全局变量了，还传啥呀？」
    • getChildren().get(0) 強轉取用——口述：「叫我们的 rectangle box get children dot get 0…… 然後就是这个长方形，那我们直接把它获取到，然后强转就完事儿了。」
    • 坑：
    • getChildren().get(0) 的強轉取用依賴 addAll 的加入順序，一旦有人調整節點順序 就會 ClassCastException。較穩的寫法是把形狀存成類別欄位。筆記疑有誤，待查： 課堂上實際走的順序是先欄位化、後又回退，中間有反覆。
    • circleBox 的外邊距口述與畫面不一致：口述是「距離上邊 0、右邊 6、下邊 0、左邊 6」， v006 畫面卻記成 new Insets(0, 5, 0, 5)。兩者都保留，筆記建議以口述為準。
    • v006 整段（類別名、色系、間距）與前後片段全面衝突，筆記判斷為解析誤讀。
    • 相關：見 W07-001、W07-004

    W07-003　開關幾何常數：弧度直接用 height、半徑 height * 0.75 / 2¶

    • 關鍵字：setArcWidth setArcHeight setRadius setStrokeWidth 0.75 height
    • 來源：第十一課 12:00–16:00、24:00–28:00｜L11_第十一课_教學筆記.md
    • 要點：這兩個數字是本課最有價值的推導過程，老師繞了一圈才想通。 弧度先想成「寬除以高，再用寬除以那個倍數」，接著自己推翻： 「那這樣不就是我們的高嗎？……好傢伙，我這考慮了半天好像直接取我們的高就行了。失誤了。」 → 結論 rectangle.setArcWidth(height) / rectangle.setArcHeight(height)，配 setStrokeWidth(1)。 圓半徑最初估「直徑差不多 10 分之 6……半徑 5 分之 3」，打算用高乘以 0.6， 實際拿畫圖工具量之後改口：「它好像有四分之三那麼大」→ circle.setRadius(height * 0.75 / 2)。
    • 程式碼：
    rectangle = new Rectangle(width, height);
rectangle.setStrokeWidth(1);          // 口述：外邊框寬度設為 1
rectangle.setArcWidth(height);        // 口述推導後的結論：弧度直接用 height
rectangle.setArcHeight(height);

circle = new Circle();
circle.setRadius(height * 0.75 / 2);  // 直徑 = height * 0.75，半徑再除以 2
    • 坑：
    • 半徑公式要自己量，不要照抄 0.6：0.6（3/5）是口述初估值，本課最終定案是 0.75。 24:00–28:00 口述又說「它的圆好像小一点。小一点，那我们应该是 3/5……那就是乘 0.6」， 但程式碼骨架與 04:00–08:00 之後的畫面都維持 height * 0.75 / 2。筆記疑有誤，待查。
    • setStrokeWidth 值有出入：口述與骨架為 1，v002 畫面曾為 2。
    • 圓半徑在過程中一度被寫成 height / 2.75 / 2，隨後修正為 height * 0.75 / 2（v003 記錄）。
    • 相關：見 W07-001

    W07-004　initStyle() 依狀態換色換對齊，手動改狀態後必須重繪¶

    • 關鍵字：initStyle() setFill setStroke setAlignment Color.rgb 重繪
    • 來源：第十一課 16:00–20:00、20:00–24:00｜L11_第十一课_教學筆記.md
    • 要點：開關的所有視覺變化（顏色 + 圓的位置）集中在同一個 private void initStyle() 裡， 依 on.get() 分成開機／關機兩套。設計的觸發點是「我們在這裡只設置了它的第一個邊框長度， 第二個它的彎曲程度，第三個它的半徑，但是我們還沒有設置顏色」。 關鍵紀律：手動改狀態（setOnOff）與滑鼠點擊之後都必須再呼叫一次 initStyle()， 講者原話：「我们开启关闭完了是不是要 init 一下 style 呀？让它的 style 发生一下变化。 不然的话不就白开了吗？」
    • 程式碼：
    private void initStyle() {
    if (on.get()) {
        // 開啟：藍底藍框 + 白圓，圓靠右
        rectangle.setFill(Color.rgb(0, 103, 192));
        rectangle.setStroke(Color.rgb(0, 103, 192));
        circle.setFill(Color.rgb(255, 255, 255));
        circleBox.setAlignment(Pos.CENTER_RIGHT);
    } else {
        // 關閉：灰底灰框 + 灰圓，圓靠左
        rectangle.setFill(Color.rgb(255, 255, 255));
        // 口述把關閉色念成「939394」又改口成「939393」——應是六位數色碼 #939393
        rectangle.setStroke(Color.rgb(0x93, 0x93, 0x93));
        circle.setFill(Color.rgb(0x93, 0x93, 0x93));
        circleBox.setAlignment(Pos.CENTER_LEFT);
    }
}

    • 漏呼叫 initStyle() 的後果是「狀態變了但顏色不變」——第一次執行測試時就出現過 「點擊後圓形滑塊會移動但樣式未到位」的現象。

    W07-013　LinkedBlockingQueue 排隊顯示提示框，避免疊在一起¶

    • 關鍵字：LinkedBlockingQueue offer peek poll Platform.runLater waitAndShow Thread.sleep ViewUtil.sleep 100 3000
    • 來源：第十三課 35:00–40:00、40:00–45:00、45:00–50:00｜L13_第十三课_教學筆記.md
    • 要點：show 可能被連續多次呼叫，提示框會疊在一起，所以要「跟 progress loading 一樣， 我們得來個隊列」。佇列 API 的教學口徑：「它是一個先進先出嘛，所以我們往後塞， 但是我們拿的時候是拿第一個……我們隊列還有一個 peek 的方法，它拿到以後它不會把這個隊列刪除。」 等待條件寫成「還沒輪到我（nowStage != stage）」，每 100 毫秒睡一次； 輪到時 Platform.runLater 顯示、停 3000 毫秒、Platform.runLater 關閉、然後 poll() 移出。 為什麼要開子執行緒：「我們不能讓，讓我們得 UI 線程調完 showAndWait 卡在這裡對不對？ 那我們要在子線程裡面去做。」
    • 程式碼：
    import java.util.concurrent.LinkedBlockingQueue;
private static final LinkedBlockingQueue<Stage> queue = new LinkedBlockingQueue<>();

    private static void waitShow(Stage stage) {
    // 將新的提示視窗加入佇列
    queue.offer(stage);

    // 啟動新執行緒處理佇列
    new Thread(() -> {
        try {
            Stage outStage;
            // 使用 peek() 檢查佇列頂端元素，不為空則進入迴圈
            while ((outStage = queue.peek()) != null) {
                Thread.sleep(100);      // 顯示前稍微等待

                // 必須透過 Platform.runLater 在 JavaFX 主執行緒更新 UI
                Platform.runLater(outStage::show);

                Thread.sleep(3000);      // 讓提示訊息停留 3 秒

                // 關閉視窗
                Platform.runLater(outStage::close);

                // 將已處理完的視窗移出佇列
                queue.poll();
            }
        } catch (Exception e) {
            // 畫面中未詳細寫出 catch 處理邏輯，僅保留 IDE 生成的預設結構
        }
    }).start();
}

    W07-014　非 Modal 提示框要自己跟主視窗跑：xProperty() / yProperty() listener¶

    • 關鍵字：xProperty yProperty addListener doubleValue 位移差 不跟隨 initModality
    • 來源：第十三課 45:00–50:00、50:00–52:00｜L13_第十三课_教學筆記.md
    • 要點：MessageBox 不設 initModality 讓主視窗仍可拖曳，副作用就是提示框不會跟著跑—— 「我們這個時候移動……它不會隨著我們窗口進行移動。它就會有一個問題，就是我們窗口在移動的時候， 誒。它還在原位置。」原因診斷講得很清楚：因為它不控制主視窗，主視窗還能動。 修法是監聽主視窗的座標 Property，用相對位移差更新子視窗座標： 「我們當前窗口的 x 座標加上 newValue 減去 oldValue」。
    • 程式碼：
    // 讓提示框跟著主視窗一起移動
primaryStage.xProperty().addListener((observable, oldValue, newValue) ->
        stage.setX(stage.getX() + newValue.doubleValue() - oldValue.doubleValue()));
primaryStage.yProperty().addListener((observable, oldValue, newValue) ->
        stage.setY(stage.getY() + newValue.doubleValue() - oldValue.doubleValue()));
    • 坑：
    • Modal 與跟隨定位是取捨關係，不能同時免費取得——要用 WINDOW_MODAL 讓主視窗不能動， 就不會有這個問題；不設 Modal 讓主視窗能拖曳，就必須自己補 listener。
    • 算的是相對位移不是絕對座標：「就是我們主窗口新的座標減去我們主窗口老的座標， 得到了它的一個偏移差。它向右偏……那麼這個偏移差就正的。它向左拉的話，這個偏移差是負的。」 寫成絕對座標會跳動。
    • newValue / oldValue 是 Number 類型，要 .doubleValue() 才能運算。
    • Property 綁定／監聽 API 只能作用在 FX 執行緒。
    • 不要在 show 的測試碼裡把 primaryStage 傳成 null：畫面層記到過 Toast.showError(null, "测试");，與本做法方向相反，筆記判斷是過渡期測試碼。
    • 多視窗聯動已實測驗收：「兩個、三個、四個，可以看到，它都是會所有的子窗口都會隨著一起 一起去動，動這個 X 座標。」
    • 畫面層另記到一條口述從未提及的支線：primaryStage.showingProperty().addListener(...) 用來監聽視窗關閉以推進佇列。筆記判定為被放棄的過渡嘗試，不是本課最終實作。
