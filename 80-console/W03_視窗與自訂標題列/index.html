    W03　視窗與自訂標題列¶

    本頁為主題式重組，內容全部來自原始的 42 份逐片教學筆記，未引入外部資訊。 每條可獨立引用；條目 ID 穩定，請勿隨意改號。

    本頁的「標題列」指自訂窗頭（stage head）：JavaFX 預設的系統窗頭被 initStyle(StageStyle.TRANSPARENT) 拔掉後，由自己用 HBox 排出來的那一列。 第二課做初版（元件、icon、按鈕），第三課做收尾（外觀、拖曳、圓角、重構）。

    條目¶

    W03-001　把視窗設成與客戶端一致的 1280×720，並設定標題與圖示¶

    • 關鍵字：setWidth setHeight setTitle getIcons primaryStage 1280 720
    • 來源：第二課 00:00–05:00｜L02_第二课_教學筆記.md；第三課 36:00–41:04（確認保留 icon 與 title）｜L03_第三课_教學筆記.md
    • 要點：尺寸直接對齊客戶端——「我們客戶端的寬是 1280，720」，所以 setWidth(1280)、setHeight(720)。標題 setTitle、圖示 primaryStage.getIcons().add(...)。 第三課收尾時特別強調：自訂窗頭不等於取代 Stage 的 icon 與 title， 把它們幹掉，任務列會退化回 Java 預設圖標、預顯示的標題也會消失。
    • 程式碼：
    primaryStage.setWidth(WIDTH);      // 1280
primaryStage.setHeight(HEIGHT);    // 720
primaryStage.setTitle("HeavenMS 控制台");
primaryStage.getIcons().add(new Image("file:src/main/resources/img/mapleicon.png"));
    • 坑：⚠️ 畫面層的三個值全部與口述衝突：尺寸 1280×720（口述）vs 1024×768（畫面 v000）vs 800×500（畫面 v002）； 標題 「HeavenMS 控制台」（口述）vs 畫面出現 10 個互不相同的字串（Console Map 冒险岛、 HeavenMS-Nop v002 控制台、HuaweiMS-hqs 登录器、HeavenMS-Map (雪融) 等）； icon 檔名 mapleicon.ico（口述）vs Mushroom.icon.png（畫面 v000）。筆記已標明以口述為準。 setResizable(false) 只出現在畫面層（v000、L03 v007），口述全篇未提，待確認。
    • 相關：見 W03-002、W03-003、W03-016

    W03-002　視窗圖示的路徑要加 file: 前綴，而且是一根斜槓¶

    • 關鍵字：file: 單斜槓 IllegalArgumentException Invalid URL or resource not found getIcons Image
    • 來源：第二課 00:00–05:00｜L02_第二课_教學筆記.md
    • 要點：這是第二課踩到的第一個坑。踩坑順序照錄：① 直接用相對路徑 → 報錯； ② 換絕對路徑、把反斜槓換成斜槓 → 還是報錯；③ 講者自己講出原因： 「因為我們的 image，它是要傳一個 URL」，最終在路徑前加 file: 才通過， 並特別提醒「這裡注意啊，是一根斜槓，不兩根斜槓」。講者反對把 icon 傳到圖床， 理由是圖床掛了本地就斷網，icon 會一直不顯示。
    • 程式碼：
    // 修改前（畫面 v001 記錄的相對路徑寫法）
primaryStage.getIcons().add(new Image("file:src/main/resources/img/mapleicon.ico"));
// 口述定案的路徑寫法：file: 前綴 + 單斜線
primaryStage.getIcons().add(new Image("file:src/main/resources/img/mapleicon.png"));

    錯誤原文（素材畫面 Console 報錯）：

    Exception in Application start method
java.lang.reflect.InvocationTargetException
...
Caused by: java.lang.IllegalArgumentException: Invalid URL or resource not found
    at javafx.scene.image.Image.validateUrl(Image.java:1110)
    at javafx.scene.image.Image.<init>(Image.java:618)
    at App.start(App.java:15)
...
Exception running application App
    • 坑：⚠️ 例外型別是 java.lang.IllegalArgumentException—— 素材錯誤原文為 java.lang.IllegalArgumentException: Invalid URL or resource not found。 ⚠️ 即使路徑寫對、不報錯了，icon 仍可能不顯示（本段收尾講者實測結果是「還是沒顯示」）。 ⚠️ 畫面層另記過絕對路徑 <DRIVE_E>，與口述「換台電腦就會報錯」的立場矛盾。 ⚠️ L02 筆記附錄的程式碼骨架註明「前綴封裝；開頭斜線數量待確認」。
    • 相關：見 W03-003、W03-004

    W03-003　JavaFX Image 解析不了 .ico，必須換成 PNG¶

    • 關鍵字：.ico PNG mapleicon.ico mapleicon.png 資源路徑
    • 來源：第二課 05:00–10:00｜L02_第二课_教學筆記.md
    • 要點：路徑改對之後 icon 還是不顯示，講者這才講出真正原因： 「因為這是一個 image，它解析不了 icon……icon 格式的它解析不了， 所以我們換成 PNG 試試。哎，它就出來了。」資源檔一律用 PNG。 這段是先花好幾輪路徑除錯、再換格式才成功的，順序反過來可省下繞路。
    • 程式碼：
    primaryStage.getIcons().add(new Image("file:src/main/resources/img/mapleicon.png"));
    • 坑：⚠️ 資源目錄在素材中互相衝突：口述為 resources 下的 image（或 img）資料夾； 畫面 v006 記為 View/close.png、v013 記為 btn/close.png／btn/exit-up.png、v009 記為 ui/login.png。 ⚠️ 第三課的素材裡完全沒有出現任何圖示或按鈕檔名，該課的資源清單是沿用第二課， 出處不可標成本課口述。
    • 相關：見 W03-002、W03-004、W03-013

    W03-004　相對路徑要經 File.toURI().toString() 才能餵給 Image，並把前綴封裝進工具類¶

    • 關鍵字：toURI toString toURL deprecated ImageViewUtil resources/img 封裝
    • 來源：第二課 15:00–25:00｜L02_第二课_教學筆記.md；第三課 36:00–41:04（延續參數化）｜L03_第三课_教學筆記.md
    • 要點：講者發現每次都用 image 都要寫一大串路徑，決定抽工具類。 轉換鏈是 File → toURI() → toString()：File.toURL() 在 JDK 原始碼裡已被標記 「過期了，已經失效」，講者逐字稿中明說「叫我們別用這個方法」。 再往前收一層：「我們是不是知道 image 就一定會放在 resource image 下面」—— 把 resources + img 前綴也一併塞進方法本體，呼叫端只傳檔名。 講者把這段稱為封裝思想：「碰到這種常用的東西，一定要利用 Java 的封裝的那個思想」。
    • 程式碼：
    public static Image getImageURL(String path) {
    File file = new File("resources/img/" + path);   // 前綴封裝；開頭斜線數量待確認
    String url = file.toURI().toString();           // File -> URI -> String
    return new Image(url, 20, 20, true, true);
}

    課堂上的除錯印碼（確認後刪除）：

    System.out.println(url);
    • 坑：⚠️ 命名與語意不符：方法名帶 URL（getImageURL），實際回傳的是 Image； 講者先說「返回的是一個 URL」，結尾又說「我們返回的就是一個 image」。筆記建議自己改叫 getImage。 ⚠️ 工具類名四方對撞：口述 ImageViewUtil（第二課）／ImageViewUtils（第三課 a007，複數）／ 畫面 util.ImageUtil（v004）／utils.ImageUtil（v005）／ui.util.ImageTool（v009）。兩者擇一即可，不影響功能。 ⚠️ 第三課 a007 抱怨 IDE 的 AI 補全外掛 CodeGeex「老給我提示一些亂乎乎的代碼」，輸入法被打斷。
    • 相關：見 W03-002、W03-013、W03-014

    W03-005　Image 不是 Node，加進容器前必須用 ImageView 包一層¶

    • 關鍵字：Image Node ImageView getChildren().add iconView 組件只能放組件
    • 來源：第二課 10:00–15:00｜L02_第二课_教學筆記.md
    • 要點：本課最關鍵的 JavaFX 觀念。直接 root.getChildren().add(image) 會失敗， 因為容器要的是 Node。講者的原話：「我們只能往組件裡面添加組件，不能添加圖片。」 解法是用 ImageView 包一層——「它是一個組件，它是繼承了 Node」—— 命名 iconView，再 add 進 stageHead。
    • 程式碼：
    Image  iconImage = new Image(ImageViewUtil.getImageURL("mapleicon.png"));
ImageView iconView = new ImageView(iconImage);
stageHead.getChildren().add(iconView);
    • 坑：⚠️ 標題文字若寫 Label，要避開 awt 的 Label，用 javafx.scene.control.Label。 ⚠️ 畫面 v003 此段被解析成 Swing（JFrame / JLabel / ImageIcon），與口述的 JavaFX 技術棧完全不同，不採信。
    • 相關：見 W03-006

    W03-006　自訂標題列是一個 stageHead HBox，裝 icon、title 與三顆按鈕¶

    • 關鍵字：stageHead HBox titleHBox stageHead 命名 Label titleLabel addAll
    • 來源：第二課 10:00–15:00｜L02_第二课_教學筆記.md
    • 要點：窗頭要放的東西講者一開始就列全了：「放的是我們的圖標、標題、最小化、最大化、關閉」， 且它們是「放了一列」→ 符合 HBox 的橫向排列，所以窗頭用 HBox stageHead。 根節點則是 VBox，窗頭佔第一行、內容區佔第二行（講者命名慣例：「我們一般根節點就用 root 表示」）。 命名有個自我修正值得記：一開始想叫 titleHBox，馬上改口—— 「就叫 stageHead 吧，不叫 title……我們其實是一個窗口的頭部」。 元件以 addAll 一次加入 stageHead。
    • 程式碼：
    HBox stageHead = new HBox();
Label  titleLabel = new Label("HeavenMS 控制台");
stageHead.getChildren().addAll(iconView, titlePane,
                               minimizeButton, maximizeButton, closeButton);
    • 坑：⚠️ 忘了把元件加進容器就完全不生效——第三課「為什麼沒生效？因為沒有添加到這個 hbox 裡面去」。 ⚠️ 命名注意：第二課口述是 stageHead，第三課 a005 又稱 stageHeader，兩者指同一個 HBox。 ⚠️ 佈局選型（BorderPane／FlowPane／GridPane／HBox／VBox／AnchorPane／StackPane 七項逐一比對後選 VBox）的完整推理屬第一／二課，已收在別頁，不在此複製。

    W03-007　讓 title 撐滿剩餘空間：setHgrow 對 Label 無效，要用 Pane 的子類¶

    W03-016　拔掉系統窗頭：initStyle 五種 StageStyle 逐一實測，定案 TRANSPARENT¶

    • 關鍵字：initStyle StageStyle DECORATED UNDECORATED TRANSPARENT UTILITY UNIFIED show() 之前
    • 來源：第三課 08:00–12:00｜L03_第三课_教學筆記.md
    • 要點：自訂窗頭做完後要「把它原來的窗體的頭給它幹掉」，API 是 primaryStage.initStyle(...)，必須在 show() 之前呼叫。講者把五個列舉值 逐一跑出來看，這是第三課知識密度最高的一段：
    值 講者判斷（節錄） 本課採用
    DECORATED 「它就是默認的」 ❌ 要幹掉的對象
    UNDECORATED 「把窗頭給去掉的……它會給你生成一個白色的背景」 ⚠️ 試過，背景是白色
    TRANSPARENT 「把窗頭去掉了……會把這個 stage 的背景給它變成透明」 ✅ 定案
    UTILITY 「生成一個只有叉的一個窗口。圖標也沒了……在任務欄上也不顯示了……很怪異的樣式」 ❌ 排除
    UNIFIED 「這不就是我們的 DECORATED 嗎」；不支援時降級成 DECORATED ❌ 沒什麼用

    UNIFIED 的直覺解釋：「Windows 的叉、最小化、最大化在右邊，Mac OS 在左邊…… 所以它會變成各個系統對應的那個風格。」 - 程式碼：

    primaryStage.initStyle(StageStyle.TRANSPARENT);
    • 坑：⚠️ UTILITY 會讓視窗在工作列上消失，講者描述為「很怪異的一個樣式」， 不小心設成這個會讓程式看起來像沒開起來。 ⚠️ 拔掉系統窗頭後，系統的拖曳、最小化、最大化、關閉全部消失，全部要自己實作。 ⚠️ UNIFIED 的差異在第二課（33:00–36:00）做圓角時才真正發揮作用， 講者當時在 UNDECORATED 與 TRANSPARENT 之間來回切才想通。 ⚠️ 畫面 v002 的 UNIFIED Javadoc 描述在 1135 字處被截斷，末句停在 The client area background is unified with the decorations. This is a。 ⚠️ ASR 把 DECORATED 轉成 decoratit／decorat。

    W03-017　無邊框後視窗拖不動：只留 offsetX／offsetY 兩個變數¶

    • 關鍵字：setOnMouseDragged setOnMousePressed getScreenX getSceneX offsetX offsetY getClickCount 雙擊最大化
    • 來源：第三課 12:00–16:00、第三課 16:00–20:00、第三課 20:00–25:00、 第三課 25:00–30:00、第三課 30:00–33:00｜L03_第三课_教學筆記.md
    • 要點：切成 TRANSPARENT 之後「我們鼠標拖進來，誒，它沒動，它動不了」。 事件掛在 stageHead 上（因為所有子元件都在它裡面）。講者親手示範了四個版本：
    • v1 直接 setX(event.getScreenX()) → 視窗會跳，指針跑到窗頭的 X、Y 上。
    • v2 只記 oldX／oldY → 視窗會漂移，因為 Stage 的 X/Y 每拖一次就變了，初始值卻不變。
    • v3 補記 oldStageX／oldStageY → 正確，但要記四個變數。
    • v4（定案）只記 offsetX／offsetY，依據是這個不變量： 「我們不管怎麼拖，鼠標相對於窗口的位置是不變的」—— 所以新滑鼠位置減去偏移量就是視窗新位置。雙擊則用 event.getClickCount() < 2 判斷、再雙擊要能還原，同樣走 isMaximized toggle。
    • 程式碼：
    /** 事件監聽集中放在方法最下面（本課的 codebase 慣例） */
private void attachStageHeadHandlers(HBox stageHead, Stage primaryStage) {

    // 拖曳：按下時記「鼠標相對視窗左上角的偏移量」
    stageHead.setOnMousePressed(event -> {
        offsetX = event.getScreenX() - primaryStage.getX();
        offsetY = event.getScreenY() - primaryStage.getY();
    });

    // 拖曳：新滑鼠位置減掉偏移量 = 視窗新位置
    stageHead.setOnMouseDragged(event -> {
        primaryStage.setX(event.getScreenX() - offsetX);
        primaryStage.setY(event.getScreenY() - offsetY);
    });

    // 雙擊：最大化 / 還原切換
    stageHead.setOnMouseClicked(event -> {
        if (event.getClickCount() < 2) {
            return;                                   // 單擊不處理
        }
        primaryStage.setMaximized(!primaryStage.isMaximized());
    });
}
    • 坑：⚠️ getScreenX/Y（螢幕座標）與 getSceneX/Y（Scene 相對座標）不能混用—— 兩者原點不同，相減會得到完全錯誤的偏移量。畫面 v003 記的正是 getSceneX/getSceneY， 與口述衝突，以口述為準。 ⚠️ 拖曳第一版失敗現象的診斷原話：「我們要拖拽的時候是以我們鼠標為基準的位置來進行拖拽， 而不是以窗口為基準的位置去拖拽。」Stage.setX/setY 設的是視窗左上角。 ⚠️ v2 漂移的根因要記清楚：只記滑鼠初始位置沒用，視窗自己的座標每拖一次都在變。 ⚠️ 雙擊第一版只會放大不會還原，補上 isMaximized toggle 才對。 ⚠️ 口述提到 ASR 誤轉兩處：變數名 old x stage y 應為 oldStageY； 「primary get Y。歷史的」應為 primaryStage.getX()（舊的）。 ⚠️ 畫面 v005 出現兩種口述沒有的寫法：if (yOffset > 0 && yOffset < 30) 的拖曳範圍限制、 final double[] 陣列繞過 Lambda 的 final 限制。兩者口述皆未出現，以口述為準。 ⚠️ 講者自訂了一條 codebase 慣例「事件監聽都放在最下面」，被追問理由時回答 「後面再說」——本課沒有回收這個伏筆。照做即可，理由待補。
    • 相關：見 W03-016、見 W14-002

    W03-018　圓角要四層同時到位，缺一層就看不出來¶

    • 關鍵字：-fx-background-radius -fx-border-radius -fx-border-width -fx-border-color 畫布透明 Stage 底板透明 圓角 10
    • 來源：第三課 30:00–33:00、第三課 33:00–36:00｜L03_第三课_教學筆記.md
    • 要點：動機來自 Win11 的審美：「我們是不是可以讓它變成圓角邊框？ 不管是……當然我們變成圓角邊框的話，Win10 也會生效啊」—— 刻意統一外觀，不是副作用。但 root.setStyle("-fx-background-radius: 10") 一開始沒生效，講者一路剝了四層才找到原因： ① root 設 -fx-background-radius: 10（沒反應）→ ② 診斷出畫布（Scene）還是直角，「我們把畫布直接設置成透明」→ ③ 發現窗口自己的底板也要透明，在 UNDECORATED（白底）與 TRANSPARENT（透明）之間來回切才想通 → ④ 補上 -fx-border-radius 也要 10，而且「如果我們不把邊框的顏色給整出來的話， 發現它還是直角」。
    • 程式碼：
    // 三、直接設在 root 上，單獨這樣設不會生效
root.setStyle("-fx-background-radius: 10;");

// 二、畫布透明（口述：把畫布直接設置成透明；本行為筆記骨架的 # 補）
scene.setFill(null);

// 三、窗口底板也透明
primaryStage.initStyle(StageStyle.TRANSPARENT);
primaryStage.setStyle("-fx-background-color: transparent;");   // # 補（口述：把窗口的基地也給設置成透明）

// 四、border 三件套：寬度 1、驗證用紅色、收尾改成 transparent
root.setStyle(
        "-fx-background-radius: 10;" +
        "-fx-border-width: 1;" +
        "-fx-border-color: transparent;" +   // 口述：把驗證用的紅色隱藏掉
        "-fx-border-radius: 10;"
);
    • 坑：⚠️ -fx-border-width 預設是 0，所以「邊框是直角的」這個現象會讓人誤判。 驗證手法值得學：先把 -fx-border-color 設成「非常顯豔的紅色」把邊框畫出來， 確認曲率對了，再把顏色收掉。看不到邊框 ≠ 邊框沒有圓角。 ⚠️ 圓角半徑與邊框半徑必須一致（皆 10），「那我們的邊框始終都是 10 弧度的曲面」。 ⚠️ root.setStyle 是整串覆寫：後一次設定會把前一次（-fx-background-radius）蓋掉， 所以三層效果要寫在同一個 setStyle 字串裡（見上方程式碼）。 ⚠️ 畫面 v008 把 -fx-border-radius: 10 放在登入項 HBox 上，與口述的「root 圓角 ＋ Stage 底板透明」是不同的事，且該處方法名為 getButton、與口述的 getImageButton 不符。
    • 相關：見 W03-015、見 W14-002
