    第四課｜VBox 容器與 ToggleButton 選單（W04-001 ～ W04-010）

    W04-001　用 VBox 當左側選單容器，逐顆把按鈕加進去¶

    • 關鍵字：VBox menuVBox getChildren().add 側邊欄 垂直排列
    • 來源：第四課 11:20–13:20、13:20–15:20｜L04_第四课_教學筆記.md
    • 要點：左側選單因為是垂直排列，容器選 VBox，命名 menuVBox。 每顆選單按鈕建好之後 menuVBox.getChildren().add(menuButton) 逐顆掛進去。 本課的實際演進是「原本裝載按鈕的容器是水平 HBox，後來改成垂直 VBox」。
    • 程式碼：
    VBox menuVBox = new VBox();
...
    menuVBox.getChildren().add(menuButton);
    • 坑：⚠️ getChildren().add(...) 只接受一個子節點，多個要用 addAll。 本課口述明說「我們這裡報錯了，是因為我們沒有 addAll」。 口述也提到 stageBody 內容不止選單，所以「我們這裡提前就 addAll 了」—— stageBody 那時先只放 menuVBox，右側內容之後再一起 addAll。
    • 相關：見 W02-007

    W04-002　setSpacing 管元件之間、setPadding 管到四周，兩者是不同的事¶

    • 關鍵字：setSpacing setPadding Insets menuVBox 間距 內距 上右下左
    • 來源：第四課 13:20–15:20｜L04_第四课_教學筆記.md
    • 要點：講者特別澄清過這兩者的差別，原話：「首先就把每一個菜單的間隔給它設置一下…… 不是 padding，setSpacing。設置每一個子組件之間內部的間格為 5 個像素…… 然後我們再設置一下 padding。就是設置子組件到四周的一個距離。」 前者管按鈕與按鈕之間的垂直間距，後者管按鈕群到容器四邊的內距。
    • 程式碼：
    VBox menuVBox = new VBox();
menuVBox.setSpacing(5); // 設定按鈕之間的垂直間距
menuVBox.setPadding(new Insets(10, 0, 0, 10)); // 設定上右下左的內邊距
// ⚠️ 衝突未解決：口述為「四邊距離都設置為 10」（應為 new Insets(10)），
//    此四參數非對稱值取自畫面 video_s02，兩者不一致。
    • 坑：⚠️ setPadding 的值有未解決衝突，本筆記未裁定。 口述是「設置子組件到四周的一個距離。我們設置為 10」（即 new Insets(10)，四邊皆 10）； 但程式碼三處（L04 第 188／363／486／549 行）與速查表採的是畫面讀到的 四參數非對稱值 new Insets(10, 0, 0, 10)（上 10、右 0、下 0、左 10）。 兩邊都保留，引用時請註明出處，不要當成定論。
    • 相關：見 W02-010

    W04-003　每個選單項做成 ToggleButton，全部收進同一個 ToggleGroup¶

    • 關鍵字：ToggleButton ToggleGroup setToggleGroup menuGroup 單選互斥
    • 來源：第四課 00:40–03:40、11:20–13:20｜L04_第四课_教學筆記.md
    • 要點：選單按鈕用 ToggleButton（帶選中狀態的按鈕），並在迴圈外先建一個 ToggleGroup，每顆按鈕都 setToggleGroup(menuGroup)。 口述原理：「你單選一個，它會把其它的 Button 的選中狀態設置為未選中。」 課堂一開始的示範就是在一個 FlowPane 裡用 for 迴圈生出 5 顆 ToggleButton 並綁同一組。
    • 程式碼：
    ToggleGroup menuGroup = new ToggleGroup();

for (MenuEnum menu : MenuEnum.values()) {
    ToggleButton menuButton = new ToggleButton(menu.getName());
    menuButton.setToggleGroup(menuGroup);
    menuVBox.getChildren().add(menuButton);
}

    課堂示範版（Console.java）：

    ToggleGroup toggleGroup = new ToggleGroup();
for (int i = 1; i <= 5; i++) {
    ToggleButton toggleButton = new ToggleButton("toggleButton");
    // 稍後在 01:22 將上一行修改為，加上數字以利辨識：
    // ToggleButton toggleButton = new ToggleButton("toggleButton" + i);

    toggleButton.setToggleGroup(toggleGroup);
    root.getChildren().add(toggleButton);
}
    • 坑：⚠️ 口述說「我們的 ToggleButton 其實和我們的普通 Button 沒有什麼很大的區別」， 差別在於它是「配合這個 ToggleGroup 來使用的」——單用 ToggleButton 不會有互斥效果。 ⚠️ 示範段的按鈕數量與命名有出入：口述先說「加了六個 Button……ToggleButton0 到 ToggleButton5」隨即自我更正「小於 5」；畫面描述的迴圈是 for (int i = 1; i <= 5; i++)， 命名 toggleButton1～toggleButton5。索引從 0 或 1 起有出入。
    • 相關：見 W04-004

    W04-004　ToggleButton 可以被反選：群組互斥不等於「一定有一顆被選中」¶

    • 關鍵字：反選 ToggleButton 未選中 互斥 提前告知
    • 來源：第四課 00:40–03:40、22:40–25:40｜L04_第四课_教學筆記.md
    • 要點：ToggleGroup 只保證「組內互斥」，不保證「至少有一顆被選中」。 口述原話：「ToggleButton 它是可以選中的，也是可以未選中的……我們再點一下 Button1， 發現 Button1 就變成未選中狀態了。」講者說「這個問題可能會帶來一些問題， 也有可能不會，提前告知給大家」。要做出「一定有當前頁」的語意，必須自己補判斷。
    • 程式碼：（講者示範時觀察到的行為，未給修法程式碼；L04 第 12 段的修法是後來用 selectedProperty() 監聽換色處理，見 W04-010）
    // L04 記錄的行為：再點一次已選中的 ToggleButton，會回到未選中狀態
    • 坑：⚠️ 本條本身就是本課明示的坑： 「ToggleGroup 只保證『組內互斥』，不保證『至少有一顆被選中』。 日後做側邊欄若要有『一定有當前頁』的語意，必須自己補判斷。」 ⚠️ 另有另一種手動單選實作會遍歷自訂列舉把全部設為未選取再設自己為選取 （menu.selectedProperty().set(false) 迴圈後再 set(true)）， 但畫面層該處寫成 MenuButton.values()，與本課實際使用的 MenuEnum 不同名， 疑為辨識誤植，筆記保留原樣。
    • 相關：見 W04-010

    W04-005　用 MenuEnum ＋ values() 動態生成側邊欄按鈕¶

    • 關鍵字：MenuEnum values() getName() constant 動態生成 for-each
    • 來源：第四課 07:20–09:20、09:20–11:20、11:20–13:20｜L04_第四课_教學筆記.md
    • 要點：口述決定「建一個 constant 的包，裡面專門放常量」，在其中定義列舉 MenuEnum。 列舉帶一個 private final String name 欄位、建構子與 getter， 之後用 MenuEnum.values() 迴圈動態生出每一顆 ToggleButton——取代先前寫死按鈕的做法， 這是本課最大的結構性改動。getter 可用 IDE 的 Alt+Insert → Generate Getters 產生。
    • 程式碼：
    package constant;   // 口述：建一個 constant 的包，裡面專門放常量

public enum MenuEnum {
    OPERATE("服起停"),
    CONFIG("服配置"),
    PLAYER("玩家管理"),
    MERCHANT("商城管理"),
    COMMAND("指令管理"),
    // 口述提到還有「WD 配置」一項，具體常數名未定
    ;

    // name
    private final String name;

    // name 的建構子
    MenuEnum(String name) {
        this.name = name;
    }

    // 透過 IDE（Alt+Insert → Generate Getters）自動產生的 getter
    public String getName() {
        return name;
    }
}
    • 坑：⚠️ MenuEnum 的列舉常數兩組對不上（重要）。 口述列出 operate（服起停）、config（服配置）、player（玩家管理）、 merchant（商城管理）、command（指令管理）、WD 配置； 畫面 v002 卻給出 OPERATE("服务器操作")、PLAYER("玩家数据")、GAMEDATA("游戏数据")、 ROBOTMATE("防脱机检测")、COMPARE("安全与黑名单")、ALL("全部")。 兩組幾乎不重疊且畫面那組為簡體中文。以口述那組為本課教學內容， 畫面那組疑為後續版本或辨識誤植。 ⚠️ 套件位置也衝突：畫面層記為 src/main/java/v0/enumtest/MenuEnum.java 與 package v2.constant；口述說 constant 包，以口述為準。
    • 相關：見 W14-008

    W04-006　stageBody 用 HBox：左邊選單、中間豎線、右邊內容¶

    • 關鍵字：HBox stageBody Separator Orientation.VERTICAL 左菜單右內容
    • 來源：第四課 07:20–09:20、13:20–15:20、28:00–30:00｜L04_第四课_教學筆記.md
    • 要點：講者逐一比較過佈局管理器（BorderPane、流式佈局、GridPane、HBox、 錨點佈局、VBox、StackPane），結論是「我就直接用最簡單的 HBox 吧。簡單好用」， 口述判定 VBox「用不上」、StackPane「也用不上」。 stageBody 是水平的 HBox，左邊放 menuVBox，右邊放內容，中間用垂直 Separator 隔開。

    W04-021　掛載與卸載：父類 init 收 Stage 與 HBox parent，setRoot 負責 add 與撐滿¶

    • 關鍵字：init(Stage primaryStage, HBox parent) setRoot HBox.setHgrow Priority.ALWAYS destroy root = null stageBody
    • 來源：第六課 28:00–32:00、32:00–36:00、36:00–40:00、40:00–44:00｜L06_第六课_教學筆記.md
    • 要點：init 要多收 Stage primaryStage（預留後期彈窗綁定）， 也把 stageBody（HBox）一併傳入、命名取短叫 parent。 掛載順序是 show() → setRoot(root)—— 把 parent.getChildren().add(root) 與 HBox.setHgrow 搬進 setRoot， 放在 show() 之後才 add，root 就永遠不可能是 null（放在前面有 null 風險）。 destroy() 則 parent.getChildren().remove(root) 後 root = null。
    • 程式碼：
    // MenuAbstract.java
package ui.menu;

import javafx.scene.layout.HBox;
import javafx.scene.layout.Priority;
import javafx.scene.layout.Region;
import javafx.stage.Stage;

public abstract class MenuAbstract {

    private Region root;                 // private：禁止子類直接操作
    private Stage primaryStage;          // 預留給後期的副窗口（彈窗）綁定
    protected HBox parent;               // 主畫面的父容器（原本的 stageBody）

    /** 由 ServerApp 呼叫：賦值 → 讓子類畫 → 掛到父容器 → 撐滿剩餘空間 */
    public void init(Stage primaryStage, HBox parent) {
        this.primaryStage = primaryStage;
        this.parent = parent;
        show();
        setRoot(root);
    }

    /** 由 ServerApp 呼叫：從父容器移除並釋放參考 */
    public void destroy() {
        if (root == null) {
            return;
        }
        parent.getChildren().remove(root);
        root = null;
    }

    /** 只給子類用：交出畫好的根節點 */
    protected void setRoot(Region root) {
        this.root = root;
        parent.getChildren().add(root);
        HBox.setHgrow(root, Priority.ALWAYS);
    }

    /** 子類一定要實作：只負責把 UI 畫出來 */
    protected abstract void show();
}
